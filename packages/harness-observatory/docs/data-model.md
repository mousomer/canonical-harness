# Canonical contract 0.1

JSON Schemas in src/harness_observatory/schemas are packaged with the library. Run, event, provenance and governance_snapshot all require schema_version. Unknown scalar facts have value:null with unavailable provenance. The fixed facts map deliberately does not accept arbitrary keys. Model is first observed model; duration_seconds, tokens and cost stay null until reliable aggregation exists. observed_span_seconds is elapsed wall-clock span of observed timestamps, not active runtime.

Events require run_id, contiguous zero-based seq, UTC timestamp or explicit null, provider-neutral event_type, a bounded typed data object, source and provenance. Vocabulary includes run/user/agent/tool/command/file/test/CI/Git/governance/intervention/stop/handoff actions. v0.1 adapters emit only actions supported by inspected evidence. Tool response does not establish process exit, test success or session completion. File actions represent attempted invocations. Free-text bodies, arguments and results never cross the default boundary.

Run IDs hash provider plus source digest. Source references are sha256 content identities and one-based line references. Identical bytes yield identical records; a changed source is a new reconstruction. Extraction warnings contain only a line, source digest and bounded error code. Unsupported and mirrored rows are explicitly reported. Malformed rows are rolled back atomically. Input EOF does not emit run.finished. Repeated Claude message fragments and tool calls may need future provider-specific deduplication; counts are observed records, not guaranteed distinct API calls.

Provenance includes source, method, confidence in [0,1], evidence_refs and extractor/version. Confidence 1 means exact extraction or mechanical transformation of cited evidence, not proof that an operator/source claim is true. Operator endpoints use 0.8, explicitly heuristic and not statistically calibrated. Candidate governance snapshots do not claim complete effective precedence. Snapshots hash sorted paths/content digests and optional-missing paths; repo_sha and provenance are associated separately, so identical governance across unrelated commits shares identity.

The JSON bundle contains run, events, warnings, governance_snapshots, git_changes and ci_runs. JSONL is the L0 input and future streaming event representation; this milestone writes canonical JSON bundles. Warehouse tables are runs, events, governance_snapshots, governance_documents, git_changes and ci_runs. JSON columns preserve canonical manifests and provenance alongside SQL columns. One run ID may be loaded once; exact duplicates are deduplicated and conflicting reconstructions rejected. Outputs are new-only, never overwrite existing warehouses.

CI rows preserve run/workflow IDs, SHA, creation/start/update timestamps, status, conclusion, matched poll timestamps and count. Exact completion stays null for REST metadata without stronger evidence. Poll intervals can be computed from timestamps; predictable-running and agent detection metrics are deferred. When no repository identifier is recorded, Git enrichment records the operator-selected local repository path with explicit provenance; this is not a historical remote URL. Endpoint commit ranges do not attribute authorship or prove commits happened during active agent execution.

Future labels use namespace, label, provenance. Future OTel adapters can derive trace IDs from run identity and spans from correlated call IDs without changing canonical storage.

Storage boundary: all real extracted, enriched and warehouse data belongs outside the project checkout. Directory names and ignore rules do not grant permission to write inside it.

Private corpus contract: a local marker records schema_version and data_root_id outside Git. Operation sidecars record corpus, extractor and enrichment versions without modifying the canonical run schema. CLI paths are constrained to an initialized non-Git root. Content-addressed raw copies retain original bytes; canonical projection and enrichment do not overwrite evidence. Supported identifiers are retained in normal private CLI processing. No output from that flow is presumed publishable.

## Canonical schema 0.2

Schema 0.2 is a coherent extraction migration. Runs now identify the extractor and poll definition, lifecycle observation, token families, compaction count, CI observation count, and governance reconstruction state. CI events distinguish status queries, blocking watches, run lists, PR checks, and artifact retrieval; conditional JSON Schema rules require the identifiers appropriate to each event. A blocking watch is not a poll. Poll definition 1 counts repeated non-blocking status queries with an explicit run ID; later state-aware semantics require another version.

Token totals sum observed nonnegative provider usage objects once per evidence record. Input, output, cache-read, and cache-write tokens remain separate; unavailable families stay null. `started_at` is the first observed timestamp with qualified provenance. Source EOF does not establish completion, so `finished_at` remains null and lifecycle status is `finish_unobserved` until direct evidence exists. Codex per-turn completion is not treated as whole-session completion.

The private data-root marker remains storage-envelope version 0.1 and is compatible with canonical bundles 0.1 and 0.2. Packaged versioned 0.1 schemas keep old smoke bundles readable and warehouse-loadable. New extraction writes only 0.2. Enrichment of an old bundle requires an explicit future migration rather than silently mixing versions. Existing 0.1 artifacts remain distinguishable by both schema and extractor version and are never reused as 0.2 census outputs.

Extractor 0.3.0 adds bounded private parsing of tool results while retaining canonical schema 0.2. Only results paired with recognized `git rev-parse` and exact-target GitHub Actions commands are inspected. The parser examines at most 64 KiB and returns only an unambiguous 40-hex Git SHA, run ID, status, conclusion, or selected normalized timestamps. Each token carries line-level provenance; surrounding output is discarded from canonical events. Ambiguous values remain absent.

The first and last tool-output SHA observations populate start/end facts with `git_command_output` provenance when direct provider metadata is absent. These are observations, not authorship claims. Poll definition 2 counts a repeated non-blocking status query only when the preceding structured status for the same run ID was non-terminal. Blocking watches, lists, PR checks, artifact commands, and the first status observation remain separate and do not increment that metric. Private outputs retain their explicit extractor and poll-definition versions; this software migration imports none of those outputs.

## Routing-analysis projection v1

The separate private SQLite tables logical_calls, raw_calls, outputs, operations, session_summary, usage_records and world_states retain free-text evidence and are not publishable. Raw references are source-digest:line. Copied call IDs with matching action signatures are deduplicated; conflicting IDs are reported. Retained UTF-8 text bytes include recorded envelopes and exclude non-text media. Backend counts are parsed only from recognized envelopes; missing tokens remain null. Response-ID usage is deduplicated separately and never attributed to tools. Surface output-group associations overlap and must not be summed. Historical Git blob tuples are candidate start states, never proof of effective or dirty instructions.

### Private projection v2

Versioned source_inventory, logical_actions, logical_action_edges, outputs, usage, operation_classifications, governance_eras, state_transitions, task_episodes, acceptance_sample and acceptance_report artifacts carry the frozen inventory identity and raw references. Measured, inferred and manually judged values are separate. Wrapper source sites are candidates, not proof of execution. Unresolved reasons and volume are first-class data. Output records preserve raw recorded text, decoded body, framing/serialization deltas and separate original/truncation metadata without token estimates. Usage preserves each authoritative record and compatible uncached subtraction; repeated provider usage is linked, not added. State-changing commands invalidate an assumed committed state unless subsequent output establishes a new SHA. Missing episode endpoints remain null. Existing checkpoint artifacts are immutable.
