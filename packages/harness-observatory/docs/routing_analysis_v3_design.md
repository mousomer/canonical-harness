# Routing analysis development contract

This is a software-method design, not an experiment report or an authorization
to collect evidence, replay an acceptance corpus, implement routes or alter a
consumer. Private inventories, observed populations, counts, findings and
experiment decisions stay in the external data root.

Every layer retains unknown/unresolved as valid outcomes. Source-command
recovery, wrapper/control-flow structure, leaf identity, output linkage, action
classification and effective instruction state are separate evidence layers.
Candidates do not establish execution; execution does not establish output
ownership; output ownership does not establish context exposure or billing.

Development fixtures should first be synthetic, covering dynamic arguments,
legacy envelopes, nesting, multiple emissions, waits, heredocs, redirects,
check-mode generators, Git-path mentions and ambiguous source/state transitions.
Any later private example collection, minimization, partitioning, tuning,
adjudication or acceptance inventory requires its own explicit protocol. Keep
development and held-out acceptance evidence separate; a software test pass
does not replace measurement acceptance or authorize governance changes.
